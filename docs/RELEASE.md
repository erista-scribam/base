# Release process (Changesets)

Scribo uses **[Changesets](https://github.com/changesets/changesets)** for semver, changelogs, and release automation. All workspace packages share one version (`fixed` group in `.changeset/config.json`).

**First release:** Nothing has been tagged or shipped yet. Workspace versions are **`0.0.0`** until the first **Version packages** PR merges on `main`. The pending changeset (`.changeset/initial-prosa-release.md`) is a **minor** bump, so that release will be **`v0.1.0`**.

## Day-to-day development

1. Branch from **`development`**, open PRs into **`development`**.
2. For user-facing or release-notable changes, add a changeset:

   ```bash
   pnpm changeset
   ```

3. Commit the new file under `.changeset/` with your PR.
4. Merge when CI is green.

## Shipping to `main`

1. Merge **`development` → `main`** when you are ready to release (include accumulated changesets).
2. On push to **`main`**, the **Version packages** workflow (`version-packages.yml`):
   - Opens or updates a **Version packages** PR if there are pending changesets, **or**
   - After that PR is merged, runs **`pnpm release:publish`**, which pushes git tag **`vX.Y.Z`**.

## Desktop builds

Pushing tag **`v*.*.*`** triggers **Desktop release** (`desktop-release.yml`): Tauri builds for macOS (arm64 + x64), Linux, and Windows, uploaded as a **draft** GitHub Release.

## What gets bumped automatically

`pnpm version-packages` (run by the Changesets action) updates:

- `package.json` versions (root, `@scribo/prosa`, `@scribo/core`, `@scribo/document-model`)
- Root **`CHANGELOG.md`** (and package changelogs as generated by Changesets)
- **`apps/prosa/src-tauri/tauri.conf.json`** via `scripts/sync-tauri-version.mjs`

You should **not** hand-edit version numbers for releases.

## Local commands

| Command                 | Purpose                                            |
| ----------------------- | -------------------------------------------------- |
| `pnpm changeset`        | Create a changeset interactively                   |
| `pnpm version-packages` | Apply changesets locally (same as CI version step) |
| `pnpm release:publish`  | Push `vX.Y.Z` tag (normally CI only)               |

## Pre-release checklist

```bash
pnpm verify:all
```

Optional on macOS: `pnpm tauri:build`

## Workflows

| Workflow             | Trigger                         | Role                                |
| -------------------- | ------------------------------- | ----------------------------------- |
| **CI**               | Push/PR → `main`, `development` | Tests, lint, typecheck, Rust checks |
| **Version packages** | Push → `main`                   | Changesets version PR + tag publish |
| **Desktop release**  | Push tag `v*.*.*`               | Tauri artifact builds               |

## Code signing (future)

macOS notarization and Windows signing are not configured. Artifacts are unsigned until signing secrets are added.
