# Written issues (bypass)

Informal, **repository-local** issue lists—not generated by GitHub.

## Naming

- **`YYYYMMDD.md`** — session or release batch (example: [20261026.md](./20261026.md)).
- **`topic-short-name.md`** — optional themed list when a date file is too narrow.

## Format

Use numbered items and inline status when helpful:

```markdown
# v0.5.0

1. Short title. **Done** — one-line resolution.
2. Open item. **Open**
```

## When to use bypass vs GitHub

| Prefer **written**                    | Prefer **GitHub Issue**                    |
| ------------------------------------- | ------------------------------------------ |
| Solo maintainer rapid list            | Public bug reports                         |
| Agent-assisted batch from one session | Needs labels, assignees, cross-linking PRs |
| Pre-public repo or low ceremony       | External contributors                      |

## Archive

When a written file is fully resolved and only historical, leave it in place or move to a dated subfolder only if clutter grows—no requirement to mirror closed GitHub issues here.
